# AITRT Methodology

AITRT separates risks from the characteristics, lifecycle stages, scenarios, controls, metrics, and evidence used to understand and manage them.

## Canonical entities
Each entity receives a stable identifier. Definitions are concise so they can be reused by tooling.

## Relationships
Relationships are first-class data. A risk can affect multiple trust dimensions, occur at multiple lifecycle stages, appear in multiple scenarios, and be addressed by multiple controls.

## External mappings
Mappings are references, not replacements for authoritative frameworks. Each mapping should identify the framework, relationship type, source, and verification status.

## Evidence
Evidence types describe artifacts that can substantiate an assessment or control implementation. They are not themselves proof of compliance.

## Evolution
New concepts should include rationale and evidence. Stable identifiers should not be casually changed; deprecated concepts should retain traceability.
