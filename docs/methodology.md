# AITRT Methodology

## 1. Concept model

AITRT separates risks from the characteristics, lifecycle stages, scenarios, controls, metrics, and evidence used to understand and manage them.

## 2. Canonical entities

Each entity receives a stable identifier. Definitions are intentionally concise so they can be reused by tooling.

## 3. Relationships

Relationships are first-class data. A risk can affect multiple trust dimensions, occur at multiple lifecycle stages, appear in multiple scenarios, and be addressed by multiple controls.

## 4. External mappings

Mappings are references, not replacements for the authoritative framework. A mapping should identify the framework, relationship type, source, and verification status.

## 5. Evidence

Evidence types describe artifacts that can substantiate an assessment or control implementation. They are not themselves proof of compliance.

## 6. Evolution

New concepts should be proposed with a rationale and evidence. Breaking changes to stable identifiers should be avoided; deprecated concepts should retain traceability.
